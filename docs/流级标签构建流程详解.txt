本文中的资金流并非指链上天然存在的原子实体，
而是面向跨链 AML 对应任务构造的可观测行为单元。
我们依据主地址 + 链 + 资产组优先的路径标识 + 30 分钟滚动时间窗口对交易进行聚合，
以降低单笔交易噪声并保留跨链转移中的金额、时间与路径一致性信息。
30 分钟窗口用于刻画短期桥接行为会话，
并在实验中通过多窗口敏感性分析验证该选择不会改变主要结论。

二、框架整体架构
------------------------------------

### 2.1 系统架构概览

该框架基于 Celer 跨链桥的官方交易锚定数据，构建端到端的流级标签。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  Celer 官方锚定数据 (Evidence Layer)                                         │
│  celer_label.csv: ETH→BNB 交易对应关系                                      │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│  流分段层 (Flow Segmentation Layer)                                          │
│  主地址 + 链 + 资产组优先路径标识 + 30分钟滚动时间窗口聚合                      │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│  流标签层 (Flow Label Layer)                                                 │
│  一对一、一对多、多对一、未匹配等模式                                         │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 各层详细说明

#### 第一层：Celer 官方锚定数据

使用 `label/celer_label.csv` 中的官方交易锚定对（兼容旧路径 `label/tx/celer_label.csv`）：
- 格式：`srcnet, srcTxHash, dstnet, dstTxHash`
- 数据来源：Celer 跨链桥官方记录
- 数据质量：高度可信，无启发式筛选

#### 第二层：流分段层

流分段将单笔交易聚合为语义单元，规则是 `tx_agg_rolling_1800s_same_asset_group_or_route`：
- 同一主地址、同一链
- 路径标识：优先 `asset_group`，若缺失则回退 `route_id`（实现：`bundle = asset_group if asset_group else route_id`）
- 同一路径标识下，相邻交易间隔不超过 30 分钟滚动窗口（1800s）

**为什么流分段重要？**
- 将交易粒度抽象为流粒度，更符合真实资金流动
- 同一用户短时间内的相关交易被聚合
- 金额覆盖率达到 99.9%

#### 第三层：流标签层

最终输出的流标签能够表达以下跨链资金流形态：

| 模式类型 | 数量 | 占比 | 说明 |
|---------|------|------|------|
| one_to_one | 5,155 | 72.32% | 一对一（流图度数 sd=1, dd=1） |
| one_to_many | 12 | 0.17% | 多 ETH 源汇入同一 BNB 流（sd=1, dd>1） |
| many_to_one | 1,961 | 27.51% | 单 ETH 流扇出多条 BNB 边（sd>1, dd=1） |
| many_to_many | 0 | 0% | - |

### 2.3 核心设计理念

**数据质量优先：**
- 使用官方桥接数据，避免启发式筛选的不确定性
- 覆盖率极高（98.9%交易 / 99.9%金额）
- 置信度高，无需额外评分筛选

**一致性原则：**
- 流分段规则保持一致
- 模式分布由当前 evidence 分段 + Celer 映射决定（见 §4.3.3 实测）
- 确保语义一致性

### 4.2 阶段一：交易→流映射

#### 4.2.1 原始交易数据

- ETH 唯一交易数：7,296
- BNB 唯一交易数：7,296
- 来源：Celer 官方桥接记录

#### 4.2.2 流分段逻辑

流分段将单笔交易聚合为语义单元，规则是 `tx_agg_rolling_1800s_same_asset_group_or_route`：

```python
current_flow = None
for summary in sorted_transaction_summaries:
    pk = (
        summary.primary_address,
        summary.asset_group,
        summary.route_id,
        summary.chain
    )

    need_new_flow = (
        current_flow is None or
        current_flow.segment_key != pk or
        (summary.timestamp - current_flow.last_ts) > 1800  # 30分钟
    )

    if need_new_flow:
        if current_flow:
            flush(current_flow)  # 保存当前流
        current_flow = create_new_flow(summary, pk)
    else:
        current_flow.add_transaction(summary)
```

- ETH 源流数：5,735

| 多笔交易的流占比 | 12.1% | 1.9% |

**说明：**

### 4.3 阶段二：聚合为流级标签 (7,296 → 7,128)

#### 4.3.1 同一流对的锚定对聚合

**为什么有数量减少？** (7,296 → 7,128，减少 168 个)

当多个交易锚定对指向相同的 `(src_flow, dst_flow)` 组合时，它们被聚合为单个流标签：

```
交易锚定对：
  (eth_tx_2, bnb_tx_45)  → (eth_flow_A, bnb_flow_Y)
  (eth_tx_3, bnb_tx_45)  → (eth_flow_A, bnb_flow_Y)
  (eth_tx_4, bnb_tx_46)  → (eth_flow_A, bnb_flow_Y)

聚合后：
  (eth_flow_A, bnb_flow_Y)  ← 1 个流标签，由 3 个交易锚定对支持
```

**聚合字段计算：**

| 字段 | 计算方式 |
|-----|---------|
| support_tx_pair_count | 该流对支持的交易锚定对数量 |
| src_amount_usd | 源流总金额 |
| dst_amount_usd | 目标流总金额 |
| matched_src_amount_usd | 匹配到的源金额 |
| matched_dst_amount_usd | 匹配到的目标金额 |
| label_confidence | 1.0（官方数据） |
| min/median/max_delay_sec | 支持的交易锚定对的延迟统计 |
| src_coverage | matched_src_amount / src_amount |
| dst_coverage | matched_dst_amount / dst_amount |

#### 4.3.2 流图构建与模式判定

**步骤1：构建流图**

```python
src_to_dst = defaultdict(set)
dst_to_src = defaultdict(set)

for flow_label in aggregated_flow_labels:
    sf = flow_label.src_flow_id
    df = flow_label.dst_flow_id
    src_to_dst[sf].add(df)
    dst_to_src[df].add(sf)
```

**步骤2：确定每个流的度数**

```python
src_degree = {sf: len(dfs) for sf, dfs in src_to_dst.items()}
dst_degree = {df: len(sfs) for df, sfs in dst_to_src.items()}
```

**步骤3：模式分类**

```python
for flow_label in aggregated_flow_labels:
    sf = flow_label.src_flow_id
    df = flow_label.dst_flow_id

    sd = src_degree[sf]
    dd = dst_degree[df]

    if sd == 1 and dd == 1:
        flow_label.pattern_type = "one_to_one"
    elif sd == 1 and dd > 1:
        flow_label.pattern_type = "one_to_many"
    elif sd > 1 and dd == 1:
        flow_label.pattern_type = "many_to_one"
    else:
        flow_label.pattern_type = "many_to_many"
```

| one_to_many | 12 | 0.17% |
| many_to_one | 1,961 | 27.51% |
| many_to_many | 0 | 0% |
| **总计** | **7,128** | **100.00%** |

### 7.1 半合成场景构建原理

半合成测试数据的核心思想是：**以真实流作为种子模板，通过人为构造的修改来创建具有已知真实对应关系的测试用例**。这种方法既保留了真实数据的分布特征，又提供了可验证的 ground truth。

**为什么使用半合成而非完全合成？**
- 完全合成的数据可能无法反映真实跨链交易的分布特征
- 半合成保留了真实流的统计特性（金额分布、时间模式等）
- 可以精确控制场景变量，便于评估算法在特定条件下的表现

### 7.2 种子模板选择（48 分层模板）

从 canonical 流标签中按 **金额四分位 × 跨链延迟三分位** 分层抽样 **48** 个 `(eth_flow, bnb_flow)` 模板（`pick_semi_synthetic_seeds`，`max_seeds=48`）。每个模板克隆 split / merge / unmatched / delay_noise 四类场景；细节见 `out/paper_full_pipeline_run/synthetic/synthetic_eval_seed_{42..46}/synthetic_seed_stratification.json`。

**【旧版本历史值】** 曾固定 8 个 ETH 模板 ID（如 `eth_flow_b14cc2dda8f743` 等）— 仅作历史说明，**当前 run 不使用**。

### 7.3 各场景详细构建过程

#### Split（分裂场景）构建

**目的：** 模拟一个源流对应两个目标流的分裂情况（如跨链后分散到两个地址）

**构建步骤：**

```
原始一对一对应：
  eth_flow_xxx__synth_split_src (100 USD)
      ↓
  bnb_flow_yyy (100 USD)

构造后的分裂对应：
  eth_flow_xxx__synth_split_src (100 USD)
      ↓
  bnb_flow_yyy__synth_split_a (50 USD)   ← 金额缩放 0.5
  bnb_flow_yyy__synth_split_b (50 USD)   ← 金额缩放 0.5
```

**关键参数：**
- 源流金额缩放：1.0（保持不变）
- 每个目标流金额缩放：0.5（各占一半）
- 总金额守恒：50 + 50 = 100

#### Merge（合并场景）构建

**目的：** 模拟两个源流对应一个目标流的合并情况（如从两个地址汇聚到一个地址）

**构建步骤：**

```
原始一对一对应：
  eth_flow_xxx (100 USD) ─┬─→ bnb_flow_yyy (100 USD)
  eth_flow_xxx'           │

构造后的合并对应：
  eth_flow_xxx__synth_merge_src1 (50 USD) ─┬─→ bnb_flow_yyy__synth_merge_dst (100 USD)
  eth_flow_xxx__synth_merge_src2 (50 USD) ─┘
```

**关键参数：**
- 每个源流金额缩放：0.5（各占一半）
- 目标流金额缩放：1.0（保持不变）
- 总金额守恒：50 + 50 = 100

#### Unmatched（未匹配场景）构建

**目的：** 模拟无匹配目标流的孤立源端流，测试算法的召回能力

**构建步骤：**

```
原始一对一对应：
  eth_flow_xxx (100 USD) → bnb_flow_yyy (100 USD)

构造后的未匹配对应：
  eth_flow_xxx__synth_unmatched_src (100 USD) → [无目标流]
  [隐藏] bnb_flow_yyy__synth_hidden_dst (0 USD)  ← 金额缩放 0.0
```

**关键参数：**
- 源流金额缩放：1.0（保持不变）
- 目标流金额缩放：0.0（完全隐藏）
- 隐藏的目标流不参与匹配，但存在于数据中用于评估算法是否能识别未匹配

#### Delay Noise（延迟噪声场景）构建

**目的：** 模拟添加随机延迟噪声的匹配对，测试算法的鲁棒性

**构建步骤：**

```
原始对应：
  eth_flow_xxx (t=100s) → bnb_flow_yyy (t=110s)  [delay=10s]

添加噪声后：
  eth_flow_xxx__synth_noise_src_0 (t=100s) → bnb_flow_yyy__synth_noise_dst_0 (t=200s)  [delay=100s]
  eth_flow_xxx__synth_noise_src_1 (t=100s) → bnb_flow_yyy__synth_noise_dst_1 (t=300s)  [delay=200s]
```

**关键参数：**
- 源流和目标流金额缩放：1.0（保持不变）
- 每个场景生成 2 个噪声副本（_0 和 _1）
- 噪声类型：时间延迟扰动
- 这些是"诱饵对"（decoy pairs），算法应该能识别它们不是真实对应

### 7.4 合成数据结构与金额缩放规则

合成流 ID 格式：`{template_flow_id}__synth_{scenario}`

| 场景 | 源流金额缩放 | 目标流金额缩放 |
|------|-------------|--------------|
| split | 1.0 (保持原样) | 0.5 (两个目标流各一半) |
| merge | 0.5 (两个源流各一半) | 1.0 (保持原样) |
| unmatched | 1.0 (保持原样) | 0.0 (目标流隐藏) |
| delay_noise | 1.0 (保持原样) | 1.0 (保持原样) |

### 7.6 评估提示

| 类型 | 数量（每 eval seed） | 说明 |
|------|------|------|

| truth_unmatched_src_flows | **48** | 无匹配源流 |
| noise_decoy_pairs | **96** | decoy 边 |

**评估指标（半合成 stress / 附录）：**
- Split / Merge recovery（Phase 2 multi-seed 主表）
- Top-k recovery、Flow-mass recall、Pair-F1
- **Unmatched / decoy：** 仅 **诊断**（Phase 2.1：阈值无关 AUROC/AUPRC；**不**宣称 strong mass-level detection）
- Phase 3 ablation：9 可跑变体 × 5 seeds；缺失 knob：`no_amount`、`no_route`、`no_address_novelty`
